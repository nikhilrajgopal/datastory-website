# Updated Datastory Site (2026)

The redesigned homepage is approved and establishes the visual direction for DataStory. Do NOT redesign or substantially change the homepage.

working off this project: The redesigned homepage is approved and establishes the visual direction for DataStory. Do NOT redesign or substantially change the homepage.

Now extend the SAME design system, visual language, typography, spacing, colors, navigation, photography treatment, interactions, and overall level of polish across ALL remaining pages in the existing website.

The goal is for the entire website to feel like one cohesive experience rather than a redesigned homepage attached to older secondary pages.

IMPORTANT:

Preserve the current redesigned homepage.

Preserve all existing routes.

Preserve existing written content unless small formatting changes are necessary for presentation.

Preserve existing images, project information, team information, links, functionality, and application/contact information.

Do not invent information.

Do not remove important content.

Continue using the established white + forest green + cream accent design system from the new homepage.

Reuse the global navigation and footer established by the homepage.

Make each page visually distinctive while clearly belonging to the same website.

Avoid simply turning every page into the exact same sequence of sections.

Redesign every existing secondary page, including the current:

About
Projects
Development
Team
Apply
Contact

and any other existing routes/pages in the repository that are still using the old design.

GLOBAL DIRECTION

Use the APPROVED HOMEPAGE as the primary source of truth.

Carry over its:

Typography

White-dominant color palette

Forest green brand color

Cream accent color

Section labels

Button styling

Link treatments

Navigation

Footer

Grid system

Spacing

Image treatment

Subtle motion

Editorial layout philosophy

Responsive behavior

Do not introduce an unrelated visual style on secondary pages.

At the same time, do not make every page look identical.

Each page should have its own composition based on its purpose.

Avoid:

Generic card grids

Excessive rounded containers

SaaS-style layouts

Gradients

Glassmorphism

Generic icon sections

Excessive animation

Repetitive hero layouts

Putting every piece of information inside a box

Continue prioritizing typography, photography, whitespace, composition, hierarchy, and restraint.

ABOUT PAGE

Redesign the About page to tell the story of DataStory.

Create a strong editorial opening rather than a generic page header.

Use the existing About content and photography.

Establish clear sections for the organization's:

Mission

Story/background

Values

Community

What makes DataStory distinctive

Where appropriate, use large statements, asymmetrical editorial layouts, full-width or offset photography, and generous whitespace.

If statistics or organization facts already exist, they can be incorporated elegantly.

Do not invent history, statistics, values, or facts.

The page should make someone understand both what DataStory does and what it feels like to be part of the organization.

PROJECTS PAGE

Make Projects one of the strongest pages on the website.

Treat it like a professional portfolio/case-study index rather than a collection of generic cards.

Show the REAL projects and clients already contained in the website.

Use larger project previews with strong typography and visual hierarchy.

Where the existing information allows, display:

Project/client name

Type of organization or industry

Type of work

Short description

Relevant image/logo

Existing additional project information

Experiment with editorial layouts such as:

Large alternating project rows

Featured project treatments

Image-led project previews

Strong typographic project listings

Avoid placing every project into a small identical rounded card.

The page should communicate that DataStory does serious, real-world technical work.

Do not invent results, clients, technologies, or statistics.

DEVELOPMENT PAGE

Redesign the Professional Development/Development page to clearly communicate how members learn and grow within DataStory.

Use the existing content.

Create a visual narrative around areas such as:

Technical development

Professional growth

Workshops

Mentorship

Project experience

Community learning

Only include areas actually supported by the existing content.

This page should be attractive to prospective members and show that joining DataStory provides meaningful development beyond simply participating in projects.

Use photography and editorial layouts instead of generic feature cards wherever possible.

TEAM PAGE

Redesign the Team page to feel human, organized, and visually polished.

Preserve all existing team members, roles, names, information, and photos.

Create a clear hierarchy if leadership/member categories already exist.

Team photos should be displayed consistently and professionally.

Avoid making the page feel like a corporate employee directory.

It should still feel like a student community.

Use clean spacing and typography.

If there are many members, a restrained grid is appropriate here, but avoid excessive rounded cards, borders, and visual clutter.

Member images should be the primary visual element.

Add subtle hover interactions only if useful.

Make sure the Team page works particularly well on mobile.

APPLY PAGE

Redesign the Apply page around one primary goal: making the application process extremely clear and inviting.

Use existing application information, timelines, requirements, FAQs, links, and calls to action.

Do not invent application dates or requirements.

Create strong hierarchy around:

Why join DataStory

Who should apply

Application process

Important dates if they currently exist

Frequently asked questions if they currently exist

Application CTA

Make the main Apply action obvious.

The page should feel exciting and welcoming while maintaining the professional design language.

Avoid overwhelming prospective applicants with dense text.

CONTACT / WORK WITH US PAGE

Redesign the Contact page so that external organizations immediately understand how to engage with DataStory.

If the current content supports it, clearly separate paths for:

Organizations/clients interested in working with DataStory

Students/general inquiries

Use the existing contact information and forms.

Do not invent contact details.

If project/service information exists elsewhere in the website, surface a concise summary here to help potential partners understand what DataStory can offer.

End with a strong, clear contact CTA.

PAGE HEROES

Secondary pages should have strong openings, but DO NOT simply copy the homepage hero onto every page.

Vary the compositions.

Examples:

Oversized typography on white

Split image/text layouts

Editorial page introductions

Full-width photography where appropriate

Large typographic statements

Forest-green hero on one particularly appropriate page

Maintain consistency through typography and spacing rather than identical layouts.

CROSS-PAGE COHESION

As you redesign, look for opportunities to create meaningful paths between pages.

For example:

Projects → Work With Us
About → Team
Development → Apply
Team → Apply
Projects → Contact
Apply → About/Development

Use restrained contextual CTAs near the bottom of pages rather than excessive buttons.

The website should encourage exploration naturally.

RESPONSIVE DESIGN

Fully redesign the secondary pages for desktop, tablet, and mobile.

Pay particular attention to:

Team grids

Project layouts

Large typography

Navigation

Image cropping

Long text sections

Application information

Buttons and CTAs

Mobile should feel intentionally designed rather than simply stacked desktop content.

FINAL CONSISTENCY PASS

After redesigning all secondary pages, perform a full-site visual consistency pass.

Check:

Typography is consistent.

Section spacing is consistent.

Navigation is consistent.

Footer is consistent.

Button styles are consistent.

Forest green is used consistently.

Cream remains an accent rather than a dominant background.

White remains the primary canvas.

Image treatments feel related.

Page transitions feel natural.

Mobile layouts work properly.

No page still visibly uses the OLD design system.

No old components visually clash with the redesigned homepage.

Do not change the approved homepage unless a very small global-component adjustment is absolutely necessary for consistency.

The final result should feel like the homepage design was intentionally created as part of one complete DataStory website.
